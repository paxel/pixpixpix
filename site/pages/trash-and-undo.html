pixpixpix never deletes a file for good: x moves it to the trash, and u puts it back.

Trashing

KeyWhereAction
ximage view, overviewmove the file to the trash
Shift+Xoverviewtrash every file of the selected file's folder, its subfolders left, after asking

A file on another drive, such as a cloud drive, goes into that drive's own trash folder, which some desktop wastebins do not show; pixpixpix finds it there.

Undo

As long as pixpixpix runs, u puts trashed files back, newest first, one per press. In the image view the file is shown in its folder; in the overview it is back as a tile in its section, selected. A whole folder trashed with Shift+X comes back with one u. If a file of the same name has taken its place, the file stays in the trash and pixpixpix says so.

KeyAction
uput the last trashed file back

The trash view

t shows the files of every trash, the home wastebin and the trash folders of mounted drives, by the day they were trashed, newest first. Only images and videos are listed, files other apps trashed included. Nothing is deleted for good here. While a large trash is read, the view counts the seconds.

On macOS

Only files pixpixpix trashed while running know where they came from; the others go back with Finder's Put Back.
